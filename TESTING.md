# Тестирование CryptoCore — спринт 3

## Автоматические тесты

Запуск из корневой папки проекта:

```powershell
python -m unittest discover -s tests -v
```

Для тестов совместимости должен быть доступен OpenSSL:

```powershell
openssl version
```

Если OpenSSL установлен вместе с Git for Windows, его можно добавить
в PATH текущего терминала:

```powershell
$env:Path += ";C:\Program Files\Git\usr\bin"
```

В третьем спринте добавлены проверки:

- типа и длины случайных данных;
- обработки отрицательной длины и сбоя источника случайности;
- уникальности 1000 ключей по 16 байт;
- доли единичных битов около 50%;
- шифрования без --key и расшифрования с созданным ключом;
- обязательности ключа при расшифровании;
- предупреждения о простых пользовательских ключах.

Проверки предыдущих спринтов сохранены, включая совместимость
с OpenSSL для CBC, CFB, OFB и CTR.

Ожидаемый результат: 55 тестов, OK.

## Подготовка NIST STS

Использован официальный NIST Statistical Test Suite версии 2.1.2:

https://csrc.nist.gov/Projects/random-bit-generation/Documentation-and-Software

Среда запуска: Windows, PowerShell.
Компилятор: GCC 16.2.0 из WinLibs, MinGW-w64, UCRT, x86_64.

Исходный код NIST STS распакован в:

```text
C:\Tools\nist-sts\sts-2.1.2\sts-2.1.2
```

Компилятор распакован в:

```text
C:\Tools\mingw64
```

Команды сборки:

```powershell
cd "C:\Tools\nist-sts\sts-2.1.2\sts-2.1.2"
$env:Path = "C:\Tools\mingw64\bin;" + $env:Path
gcc -std=gnu99 -O2 -fcommon -I include src/*.c -o assess.exe -lm
```

Параметры -std=gnu99 и -fcommon используются для совместимости
исходного кода NIST STS с современным GCC.

## Подготовка случайных данных

Из корневой папки CryptoCore с активированным виртуальным окружением:

```powershell
python -c "from pathlib import Path; from cryptocore.csprng import generate_random_bytes; Path('nist_test_data.bin').write_bytes(generate_random_bytes(10_000_000))"
```

Файл содержит 10 000 000 байт, полученных через функцию проекта
generate_random_bytes, которая использует os.urandom.

Проверка размера:

```powershell
(Get-Item nist_test_data.bin).Length
```

Ожидаемый размер — 10000000 байт.

Файл исключён из Git через .gitignore:

```gitignore
/nist_test_data.bin
```

## Запуск NIST STS

Из каталога NIST STS:

```powershell
.\assess.exe 1000000
```

Число 1000000 задаёт длину одной последовательности в битах.

Ответы на вопросы программы:

| Параметр | Значение |
|---|---|
| Generator Selection | 0 — Input File |
| User Prescribed Input File | Полный путь к nist_test_data.bin |
| Применить все тесты | 1 |
| Parameter Adjustments | 0 — параметры по умолчанию |
| How many bitstreams? | 80 |
| Input File Format | 1 — Binary |

Использованный путь к файлу:

```text
C:/Users/moroz/PycharmProjects/CryptoCore/nist_test_data.bin
```

Общий объём: 80 последовательностей по 1 000 000 бит,
то есть 80 000 000 бит, или 10 000 000 байт.

Запущены все 15 видов статистических тестов.

Итоговый отчёт сформирован в:

```text
experiments/AlgorithmTesting/finalAnalysisReport.txt
```

Его копия сохранена в проекте: [nist_results.txt](nist_results.txt).

## Интерпретация результатов

Уровень значимости для отдельной последовательности — 0,01.
Столбец PROPORTION показывает количество последовательностей,
прошедших соответствующую проверку.

Для 80 последовательностей точная нижняя граница числа успешных
результатов составляет примерно 76,53, поэтому требуется минимум 77.
В одном варианте Non-overlapping Template получено 76/80:
это отдельное отклонение ниже указанной границы.

Для Random Excursions и Random Excursions Variant условиям применимости
удовлетворила 51 последовательность из 80. Остальные последовательности
не учитывались в этих проверках; это не означает их провал.

Столбец P-VALUE итогового отчёта относится к проверке равномерности
распределения p-values. Для него применяется порог 0,0001,
а не 0,01. Все значения этого столбца выше 0,0001.

Согласно разделу 4.2.2 NIST SP 800-22 Rev. 1a, для статистически
значимой оценки равномерности требуется не менее 55 последовательностей.
Поэтому оценка равномерности для двух тестов Random Excursions
ограничена: в данном запуске использована 51 последовательность.

Большинство проверок пройдено, массовых отклонений не обнаружено.
Результат соответствует критерию задания, допускающему небольшое
число статистических отказов.

Статистические тесты не доказывают криптографическую стойкость генератора.
В проекте источником случайности служит системная функция os.urandom.

Документация:
https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-22r1a.pdf

- параметры тестов: по умолчанию;
- количество последовательностей: 320;
- формат: 1 — Binary.

Проверено 40 000 000 байт:
320 последовательностей по 1 000 000 бит.

Полный отчёт: [nist_results_40mb.txt](nist_results_40mb.txt).

### Результаты

Все итоговые p-values проверки равномерности выше 0,0001.
Минимальное значение в отчёте — 0,011086.

Для выборки из 320 последовательностей нижняя граница числа успешных
результатов составляет примерно 311,46, поэтому требуется минимум 312.
Один шаблон Non-overlapping Template дал 311/320.
Остальные строки с выборкой из 320 последовательностей соответствуют
критерию доли успешных результатов.

Для Random Excursions и Random Excursions Variant подошли
189 последовательностей. Это превышает рекомендованный минимум
55 последовательностей для оценки равномерности p-values.

Нижняя граница числа успешных результатов для этой выборки —
примерно 183,006, поэтому требуется минимум 184:

- Random Excursions: от 184/189 до 188/189;
- Random Excursions Variant: от 187/189 до 189/189.

Большинство проверок пройдено, массовых отклонений не обнаружено.
Зафиксировано одно отклонение по доле успешных последовательностей.
Результат соответствует критерию задания, допускающему небольшое
число статистических отказов.

Ограничение размера выборки для Random Excursions, отмеченное
в первом запуске, в дополнительном запуске устранено.
