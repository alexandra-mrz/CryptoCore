# CryptoCore

Учебная программа для шифрования и расшифрования файлов с помощью AES-128 в режимах ECB, CBC, CFB-128, OFB и CTR.

## Зависимости

- Python 3.10 или новее.
- pip — для установки проекта.
- setuptools — для сборки пакета.
- pycryptodome — для выполнения операций AES.
- Git — для хранения истории проекта.
- OpenSSL — для тестов совместимости.

Зависимости сборки и библиотека pycryptodome устанавливаются автоматически.
Для тестирования используется встроенный модуль unittest.

## Установка в Windows PowerShell

Откройте терминал в корневой папке проекта.

1. Создайте виртуальное окружение, если его ещё нет:

   ```powershell
   python -m venv .venv
   ```

2. Установите проект в это окружение:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -e .
   ```

3. Активируйте окружение:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

4. Проверьте доступность команды:

   ```powershell
   cryptocore --help
   ```

Если окружение уже активировано в PyCharm, достаточно выполнить:

```powershell
python -m pip install -e .
cryptocore --help
```

## Использование

Создайте файл plaintext.txt с произвольным текстом.

Шифрование:

```powershell
cryptocore --algorithm aes --mode ecb --encrypt --key 000102030405060708090a0b0c0d0e0f --input plaintext.txt --output ciphertext.bin
```

Расшифрование:

```powershell
cryptocore --algorithm aes --mode ecb --decrypt --key 000102030405060708090a0b0c0d0e0f --input ciphertext.bin --output decrypted.txt
```

Ключ должен содержать ровно 32 шестнадцатеричных символа, представляющих 16 байт. Для расшифрования используется тот же ключ.

Аргументы --algorithm, --mode, --key, --input и --output обязательны.
Нужно указать ровно одну операцию: --encrypt или --decrypt.
Аргумент --iv необязателен и разрешён только при расшифровании CBC, CFB, OFB и CTR.

При успешном выполнении программа завершается с кодом 0.
При ошибках аргументов или ключа возвращается код 2.
При файловых ошибках или ошибках расшифрования возвращается код 1.
Сообщения об ошибках выводятся в stderr.

## Проверка полного цикла

После шифрования и расшифрования сравните файлы побайтово:

```powershell
python -c "from pathlib import Path; print('Файлы совпадают:', Path('plaintext.txt').read_bytes() == Path('decrypted.txt').read_bytes())"
```

Ожидаемый результат:

```text
Файлы совпадают: True
```

## Автоматические тесты

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют:

- восстановление текстовых, бинарных и пустых данных;
- добавление и проверку PKCS#7;
- обработку неправильной длины ключа и шифротекста;
- совпадение шифротекста с готовой реализацией ECB и PKCS#7 из pycryptodome;
- полный цикл через командный интерфейс;
- ошибки аргументов и файлового ввода-вывода.

## Структура проекта

- src/cryptocore/cli_parser.py — аргументы командной строки и выполнение операции.
- src/cryptocore/file_io.py — чтение и запись бинарных файлов.
- src/cryptocore/modes/ecb.py — обработка блоков и дополнение PKCS#7.
- src/cryptocore/__main__.py — точка входа.
- tests/ — автоматические тесты.

Примитив AES используется из pycryptodome. Разбиение данных на блоки по 16 байт, дополнение PKCS#7 и его проверка реализованы в проекте.

## Режимы шифрования

Параметр --mode принимает следующие значения:

| Режим | Особенности | PKCS#7 |
|---|---|---|
| ecb | Независимая обработка блоков, без IV | Используется |
| cbc | Сцепление блоков шифротекста | Используется |
| cfb | Обратная связь по шифротексту, сегмент 128 бит | Не используется |
| ofb | Гамма не зависит от открытого текста | Не используется |
| ctr | Счётчик начинается со значения IV и увеличивается для каждого блока | Не используется |

В CTR используется 128-битный счётчик с порядком байтов big-endian.
CFB, OFB и CTR сохраняют длину данных, включая неполный последний блок.
При записи файла дополнительно добавляется 16-байтный IV.

Логика режимов реализована в файлах ecb.py, cbc.py, cfb.py, ofb.py
и ctr.py внутри src/cryptocore/modes/.
Библиотека выполняет только операции AES над отдельными блоками.
Готовые реализации режимов используются в тестах для сравнения.

## Обработка IV

Для CBC, CFB, OFB и CTR при каждом шифровании создаётся случайный
16-байтный IV через os.urandom(16).

Выходной файл имеет формат:

```text
<16 байт IV><байты шифротекста>
```

Передавать --iv при шифровании запрещено.

При расшифровании:

- Без --iv первые 16 байт файла используются как IV, оставшаяся часть — как шифротекст.
- С --iv используется переданное значение, а весь входной файл считается шифротекстом без заголовка.
- IV передаётся как 32 шестнадцатеричных символа.
- Если --iv не указан и файл короче 16 байт, программа сообщает об ошибке.

ECB не использует IV, его формат файла остаётся прежним.

## Пример использования CBC

Создайте plaintext.txt с произвольным содержимым.

Шифрование с автоматическим созданием IV:

```powershell
cryptocore --algorithm aes --mode cbc --encrypt --key 000102030405060708090a0b0c0d0e0f --input plaintext.txt --output ciphertext.bin
```

Расшифрование с извлечением IV из файла:

```powershell
cryptocore --algorithm aes --mode cbc --decrypt --key 000102030405060708090a0b0c0d0e0f --input ciphertext.bin --output decrypted.txt
```

Для остальных новых режимов замените cbc на cfb, ofb или ctr.

Для расшифрования файла без заголовка IV, например созданного OpenSSL,
передайте IV явно:

```powershell
cryptocore --algorithm aes --mode cbc --decrypt --key 000102030405060708090a0b0c0d0e0f --iv 00112233445566778899aabbccddeeff --input openssl_cipher.bin --output decrypted.txt
```

Ключ и IV должны совпадать со значениями, использованными при шифровании.

## Проверка совместимости с OpenSSL

Для этих проверок требуется установленный OpenSSL.
Проверьте его доступность:

```powershell
openssl version
```

Если OpenSSL установлен вместе с Git for Windows в указанной ниже папке,
но команда не найдена, добавьте путь для текущего терминала:

```powershell
$env:Path += ";C:\Program Files\Git\usr\bin"
```

Запустите тесты совместимости:

```powershell
python -m unittest discover -s tests -p "test_openssl.py" -v
```

Сценарий tests/test_openssl.py проверяет каждый режим:
CBC, CFB-128, OFB и CTR — в двух направлениях.

1. CryptoCore → OpenSSL:
   - CryptoCore шифрует исходный файл.
   - Тест извлекает IV из первых 16 байт.
   - Оставшийся шифротекст передаётся OpenSSL для расшифрования.
   - Результат побайтово сравнивается с исходным файлом.

2. OpenSSL → CryptoCore:
   - OpenSSL шифрует исходный файл с заданными ключом и IV.
   - CryptoCore расшифровывает его с явным параметром --iv.
   - Результат побайтово сравнивается с исходным файлом.

Для каждого направления проверяются пустые данные, данные длиной
16 байт и бинарные данные длиной 255 байт с неполным последним блоком.

Тестовые файлы создаются во временной папке и автоматически удаляются.
Фиксированный IV используется только для проверки совместимости.

Сценарий содержит два тестовых метода, внутри которых выполняются
24 проверки: четыре режима, три варианта данных и два направления.

Ожидаемый результат:

```text
Ran 2 tests
OK
```

При отсутствии OpenSSL тесты завершаются ошибкой.
